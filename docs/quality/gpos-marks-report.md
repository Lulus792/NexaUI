# OpenType mark positioning — 2026-10-16

## Change and contract

The shared C17 shaper now attaches combining glyphs using GPOS MarkBase,
MarkLig and MarkMark (types 4/5/6). Private state retains logical ligature
components through GSUB, including ignored marks and nested substitutions.
GPOS extension type 9 and GSUB extension type 7 unwrap supported lookups.
GDEF class definitions and mark sets supply lookup filters. Public C structure
layouts and function signatures are unchanged.

Attachments form a backward logical parent graph. A final forward pass resolves
parent placement and final advances after GPOS and legacy kerning. Its RTL
origin calculation follows NexaUI's visual glyph placement. Parent searches
retain the previous eligible glyph rather than rescanning every prefix; GSUB
streams compaction rather than moving the remaining suffix per ligature.
Each selected table retains its 4,000,000-operation work budget. These are
local algorithm properties, not a whole-layout throughput guarantee.

Anchor format 2 uses design-coordinate fallback without hinting. Format 3
applies signed packed Device deltas at integer ppem; fractional ppem and
VariationIndex retain design coordinates. Ordinary SinglePos/PairPos Device
ValueRecords, contextual lookups, cursive attachment, script preprocessing,
variable-font deltas and comprehensive real-font shaping remain outside this
subset. Missing required GDEF filter data now causes an error instead of the
old unsupported-flag skip. Public shape outputs remain transactional.

The implementation was checked against primary OpenType descriptions of
[GPOS anchors and mark lookups](https://learn.microsoft.com/en-us/typography/opentype/spec/gpos),
[GDEF classes and mark sets](https://learn.microsoft.com/en-us/typography/opentype/spec/gdef)
and [lookup filtering](https://learn.microsoft.com/en-us/typography/opentype/spec/chapter2).

## Regression and rendering

`tests/test_gpos_marks.c` builds an original synthetic SFNT fixture. Before
the implementation, its public `nx_shape_text` assertion failed on the LTR
mark offset: fallback centering did not reach the font's anchor. The completed
test covers:

- LTR and RTL base attachment, nonspacing and spacing-mark advances, uncovered
  bases/marks blocking a previous attachment, stacked marks, later parent
  placement and filtered pair kerning.
- Retained marks on different components of `fi` and nested `ffi` ligatures;
  MarkMark cannot incorrectly stack marks belonging to different known
  components. Direct cmap ligatures use the last component fallback.
- GDEF class formats 1/2 and mark-set precedence, both coverage formats,
  anchors 1/2/3, signed 2/4/8-bit Device deltas and packed-word boundaries,
  fractional ppem and default-instance VariationIndex fallback.
- GSUB/GPOS extension wrappers, recursive/overflowing extension references,
  optional absent parent anchors, required source anchors and every truncated
  prefix of the base-positioning table. Error cases preserve caller output.
- 10,000 ligatures with retained marks and a chain of 10,000 attached marks.
  These validate bounded completion and component/offset results; no latency
  guarantee is inferred.
- Actual outline decoding, text layout, glyph masks and headless composition.
  Pixel checks locate the base and two stacked accents and their separating
  gap. An optional output argument writes a 128×96 PPM. Its enlarged local
  rendering was visually inspected. The rectangles deliberately test positions,
  not typographic quality of real fonts.

Local commands (Visual Studio builds also use `--config Debug`/`-C Debug`):

```sh
cmake --build BUILD_DIR --target nexaui_gpos_mark_tests
ctest --test-dir BUILD_DIR -R '^nexaui_(gpos|gpos_marks|gsub|shape|text_layout|text_stamp|font|cmap|glyf|raster|glyph_cache|font_collection)$' --output-on-failure
BUILD_DIR/nexaui_gpos_mark_tests out/gpos-marks.ppm
```

The twelve targeted tests passed with MSVC 19.38.33145 on Windows, static and
shared Debug builds, and with Clang 22.1.3 on Alpine 3.24/WSL2 using
AddressSanitizer, UndefinedBehaviorSanitizer and `ASAN_OPTIONS=detect_leaks=1`.
The Linux shared Debug build with GCC 15.2.0 passed the same twelve tests.
The complete local Windows static suite executed 98 passing tests and skipped
one clipboard test (99 registered, 205.94 seconds). Native NexaCloud, UIA and
compact UIA cases passed; the skip is not counted as clipboard acceptance.
The portable tests do not establish macOS runtime or native screenreader
acceptance; fresh CI results are recorded separately when available.

## Combined-table fuzz campaign

The GPOS fuzzer accepts raw GPOS or `NXP2` bundles with GPOS/GDEF/GSUB tables.
Six seeds generated by the public-API mark test supplement the existing single/
pair seed. Fixed and mutated glyph sequences run through GSUB provenance,
metrics, GPOS and attachment resolution. Seed generation is reproducible:

```sh
BUILD_DIR/nexaui_gpos_mark_tests --write-seeds fuzz/corpus/gpos
ASAN_OPTIONS=detect_leaks=0 UBSAN_OPTIONS=halt_on_error=1 python3 tools/run_fuzz_campaign.py --build-dir out/vulkan-sanitize --output-dir out/gpos-mark-fuzz-20261016 --target gpos --runs 50000 --seed 181016 --wall-timeout 180
```

On Alpine 3.24/WSL2, Clang 22.1.3/libFuzzer completed 50,000 runs with
`-max_len=2048`, seven starting seeds, exit 0 and 1,819 final coverage counters
in 30.131 seconds. ASan and UBSan reported no finding. Coverage counters are
instrumented edges, not a percentage or correctness proof. LeakSanitizer was
disabled for this libFuzzer campaign because of the previously documented
Alpine runtime allocation; leak checks remained enabled for the twelve CTests.
The [campaign receipt](gpos-marks-fuzz.json) retains the exact executable and
starting-seed hashes. The reviewed test font is synthetic; real-font corpus
comparison and complex-script conformance remain open.
