# NexaCloud UI delivery

The two user-provided designs establish the visual direction: dark navy surfaces,
cyan/blue emphasis, quiet borders, rounded content groups, a persistent navigation
column, dashboard metrics and a file grid with an inspector. The reference
implementation is [examples/nexacloud](../examples/nexacloud/README.md).

NexaCloud is the current integration priority. It exercises additions to the
general C17 toolkit instead of introducing a NexaCloud-specific public API.
There are no external UI/window/font dependencies and no browser-based surface.
Native OS window decorations, input, IME, clipboard, scale and renderer adapters
remain separate from the common scene.

## Component and state contract

| Element | Reusable composition | State/interaction |
| --- | --- | --- |
| Navigation | Navigation action, icon, text, badge | selected, hover, held, focus, keyboard activation |
| Summary/content card | Card and child labels/images | semantic panel, named status plus color |
| Transfer | Card, icon, labels, progress | determinate fraction, pause/resume demo state |
| File tile | Tile action, thumbnail, labels | selected, focus, full accessible name, grid/list composition |
| Inspector | Card in a scroll area | close, open, share, favorite, editable description |
| Search | Existing text-field widget | owned draft, empty results, IME/clipboard adapter when native |
| Rate chart | Existing line/triangle primitives | two named series with separate colors |
| Dialog | Existing modal/focus trap | Escape/outside dismissal, trigger focus return |
| Appearance | Semantic theme tokens | Midnight/Light runtime switch, direct reduced-motion behavior |

Text colors and accent/selection pairs are covered by the theme contrast tests.
Status also has names and values; color is not the sole indicator. Icons are
authored vector paths. The sample thumbnail artwork is generated by the example.
Expensive monochrome text rasterization is retained in explicit owned text stamps;
the application releases them after renderer use ends.

## Delivery sequence

1. **Implemented:** reusable components and the shared overview/file scene;
   normalized-input workflow, native Windows runner and D3D12 captures.
2. **Implemented initial native scene:** Vulkan core shapes, nested clips,
   straight-alpha composition and bitmap/glyph upload render this same scene
   on X11 and Wayland. Overview, file and compact GPU captures match the software
   reference byte-for-byte. Bounded retirement, upload allocation failures and
   rebuild/recovery remain covered. Hardware, physical-input/IME and display
   acceptance are still required.
3. **Implemented initial native scene:** AppKit window/input and Metal
   shape/alpha/image/lifecycle tests pass in static/shared native CI. The C17
   Metal runner's overview/file/compact captures match headless and each other
   across both variants; their actual 1024×642 / 820×645 client sizes were
   visually reviewed. The compact-details case is newly authored. Wide-display,
   Retina and physical/assistive acceptance remain open; public APIs have no
   platform types.
4. **Pending:** large-text reflow, physical DPI/monitor and 4K checks, full native
   keyboard walkthroughs, OS accessibility bridges/screenreaders, performance
   budgets, packaging and release acceptance on each supported OS.

No target OS is accepted solely because the common scene compiles or renders
headlessly. The [example matrix](../examples/nexacloud/README.md#verification-and-remaining-platform-work)
and [local validation report](nexacloud-validation.md) record the current scope.
Server authentication, storage, networking and real
cloud operations belong to the later NexaCloud integration, outside this UI example.
