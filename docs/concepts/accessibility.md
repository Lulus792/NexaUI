# Accessibility semantics

NexaUI records a backend-independent semantic tree in each UI context. Semantic nodes describe what a control means without relying on color, geometry rendering or a particular operating system. The current C API stores role, stable ID, parent, logical bounds, accessible name, description, value, state and supported actions. This is the foundation for future Windows UI Automation, macOS accessibility and Linux AT-SPI bridges; none of those native bridges is implemented yet.

Call `nx_semantics_add` during frame construction in parent-first order. A parent ID of zero creates a root. IDs must be unique in that frame and can be derived from `nx_id`, matching an interactive region's ID when the same control has input behavior. Interactive roles such as button and text field require a nonempty accessible name. Strings are copied, checked as UTF-8 and rejected if they contain embedded NUL bytes. A frame can contain multiple roots for future multi-window use, though the current Win32 window API has not yet connected semantic roots to native windows.

After `nx_end_frame`, `nx_semantics_count`, `nx_semantics_get` and `nx_semantics_find` expose a deterministic parent-first snapshot. Returned string spans are borrowed until the next `nx_begin_frame` or context destruction. Semantic storage and lookup tables are reused across frames. `NX_SEM_FOCUSED` is derived from `nx_focus_id` when queried; callers cannot set it directly. Other state flags, such as disabled or checked, and action flags are supplied by the widget/application. Later widget APIs must keep those flags consistent with actual interaction behavior.

This layer currently stores action capabilities but does not dispatch accessibility actions. Screenreader transport, announcements, platform focus synchronization, text ranges, live regions and native inspection remain pending. The `examples/03_interactive_region` program demonstrates a semantic window/button tree alongside separate hit testing and headless drawing. `nx_widget_register` unifies a widget's semantic node and optional hit region under one stable ID; `examples/09_custom_widget` demonstrates that path.
The [headless accessibility example](../../examples/12_accessibility/README.md) prints a verified semantic snapshot after Tab, Space and Enter input. It checks tree structure, action flags and derived states without claiming native screenreader support.
Basic controls and value controls use that shared registration path. The numeric field records the current draft as a text-field value and marks invalid or out-of-range drafts with `NX_SEM_INVALID`; its committed number remains separately queryable from the field object.

A password text field created with `nx_text_field_create_password` and drawn with `desc.password` sets `NX_SEM_PROTECTED` and stores an empty semantic value, including after edits. The flag gives future native bridges the information needed to expose a protected input role without publishing its plaintext. Native bridge behavior and screenreader acceptance are still pending.
