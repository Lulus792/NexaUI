# Identity, hit testing and focus

NexaUI now retains one frame of interactive hit regions inside each UI context. During frame construction, call `nx_interact_region` with a stable nonzero ID, a logical hit rectangle and focus/disabled flags. Register regions in visual order; the last registered overlapping region is topmost. Disabled regions block input to regions behind them but never activate. Duplicate IDs in one frame return `NX_ERROR_STATE`.

At `nx_begin_frame`, the newly queued input events are routed against the regions registered in the **previous** completed frame. This lets an immediate/declarative UI rebuild return click and focus state while retaining a stable interaction tree. A newly added region becomes interactive after its first completed frame. During the current frame, `nx_interact_region` returns hover, held, logical focus and the number of activations for that ID. It also registers the region for the next frame. If a region disappears, `nx_end_frame` clears its focus and capture state. The region buffers and ID lookup tables are reused after warmup.

The pointer uses half-open rectangles and checks topmost registration first. Left-button down captures the target ID; a release over that same ID records a click. Dragging outside preserves held state until release but does not click. Pointer cancel or OS focus loss ends capture. A press and release in one frame still produce an activation. Pointer coordinates come from the normalized event stream and stay in logical pixels.

Tab and Shift+Tab traverse enabled focusable regions in registration order, wrapping at the ends. Enter and Space activate the focused region on key release. `nx_focus_set` selects a registered enabled focusable ID programmatically, or clears focus with ID zero. Logical focus is kept across frames while the region remains registered.

An active popup or modal marks its backdrop, panel and child hit regions with one overlay ID. Pointer, wheel and Tab routing ignore background regions while the overlay is active. Tab and Shift+Tab wrap among focusable overlay children; the panel is a fallback when it has no focusable children. Opening an overlay remembers the previous focus, and dismissal restores it if that region still exists. `nx_overlay_close` deactivates an overlay between frames before the next queued events are routed. Only one overlay is supported per frame. Nested focus scopes, directional navigation and native accessibility focus bridges remain future tasks.

Menu items add a sibling navigation group to their hit region. Left/Right navigate a menu bar, Up/Down navigate a menu, and Home/End select its first or last enabled item. Disabled siblings are skipped; focus remains inside an active popup scope.

`NX_REGION_SCROLLABLE` routes wheel deltas to the innermost scrollable hit region under the pointer, even when a child region is topmost for clicks. The routed deltas appear in `nx_interaction_state.wheel_x/y`; disabled regions are skipped. `nx_scroll_area_begin` combines this region with painting, semantics and a balanced viewport clip. Hit regions registered inside a clip inherit its bounds automatically. Custom widgets can still combine interaction state with layout rectangles and render commands, as in `examples/03_interactive_region`.
