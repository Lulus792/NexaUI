# Custom widget contract

NexaUI lets an application define widgets as ordinary C functions. The application owns widget data and chooses when to measure, register and draw each widget during a frame. `nx_layout` supplies measured/arranged rectangles, `nx_widget_register` binds a stable ID and bounds to both the semantic tree and the optional hit region, and drawing functions append commands in paint order. This model does not require a widget subclass, a renderer-specific handle or an allocation per widget.

`nx_widget_desc.semantic` carries the accessible role, parent ID, bounds, name, description, value, state and actions. `NX_WIDGET_INTERACTIVE` adds a hit region using that same ID and bounds; `NX_WIDGET_FOCUSABLE` adds keyboard focus and requires `NX_ACTION_FOCUS`. The disabled semantic state automatically disables the hit region. A display widget may use zero flags and no actions. The caller receives pointer/keyboard interaction state and can update application-owned data before registering following semantic nodes.

Register semantic parents before children. `nx_widget_register` copies semantic strings as `nx_semantics_add` does. If hit-region registration fails after semantic insertion, the insertion is rolled back so the frame has no partial widget record; a retry with the same ID can succeed. Registration does not draw or change application data. The caller should finish drawing only after successful registration. Draw commands already emitted by an application callback remain the caller's responsibility.

The custom widget should use `nx_id` or another stable nonzero ID every frame, and re-register each visible widget in source order. Pointer events are routed against the previous frame's regions. A widget removed from a frame loses focus and capture when that frame ends. A widget becoming disabled also loses focus/capture at frame end. Semantic snapshots are available after `nx_end_frame` and retain copied strings only until the next frame.

The [custom widget example](../../examples/09_custom_widget/README.md) defines an action button and progress display. It uses layout rectangles, theme tokens, headless rendering and a semantic progress value updated after pointer and keyboard activation. Advanced built-in widgets, native accessibility action dispatch and a retained application state registry are separate tasks.

## Display widgets

`nx_label` draws an existing `nx_text_layout` and registers its copied UTF-8 source as a text semantic name. The caller supplies the semantic bounds, drawing origin, color and glyph-cache budget; the caller also keeps the font collection and source font bytes alive through the call. Its glyph masks become frame-owned drawing commands. The label does not clip to its bounds; use `nx_push_clip` when needed.

`nx_rich_label` shares the same semantic name and ownership contract while drawing ordered inline color, background, underline and strike spans through `nx_draw_rich_text_layout`. It rolls back its semantic node when styling or painting fails, allowing a retry in the same frame. See [the rich-text contract](text.md).

`nx_image` draws a borrowed RGBA8 or A8 bitmap scaled into its bounds and registers an image semantic node. It requires a nonempty accessible name; for purely decorative imagery, call `nx_draw_bitmap` directly. Bitmap pixels must remain readable until rendering completes. `nx_separator` draws its rectangle and registers a separator semantic node. Both take a caller-selected color, so theme tokens can be resolved before calling them.

`nx_layout_spacer` inserts a fixed-width, fixed-height leaf into a layout tree. It emits neither drawing commands nor a semantic node. All three display drawing calls roll back their new semantic node when drawing fails, allowing a retry with the same ID in the current frame. Their parent semantic node must already be registered.

## Basic controls

`nx_button`, `nx_checkbox`, `nx_radio` and `nx_toggle` draw theme-colored controls and register focusable hit regions with matching semantic nodes. Each requires a stable ID, bounds and nonempty accessible name in `nx_control_desc`. An optional text layout draws a visible label at `label_origin`; keep its fonts alive through the call and supply a positive glyph-cache budget. Without a text layout the control remains a visual shape with an accessible name. The caller chooses label placement and supplies the layout rectangle.

The calls return `nx_interaction_state`. Buttons report activation counts; checkboxes and toggles flip their caller-owned boolean for each odd number of activations; radios write their nonzero option ID into the caller-owned selection. Pointer and Enter/Space activations use the same state path. A disabled control reports no activation and has `NX_SEM_DISABLED`. The checked semantic state and drawing reflect the updated model in the same frame. Controls roll back their semantic node, hit region and drawing commands if painting fails, leaving the application model untouched.

For `nx_toggle`, an optional `switch_transition` animates the thumb position across frames. Supply a finite nonnegative `switch_duration_seconds`; zero snaps immediately. `switch_easing` accepts linear or smoothstep, with zero selecting smoothstep. The checked value and semantic state change immediately, while reduced motion snaps the thumb to the new position. A failed paint restores the transition as well as the control state. See [Animation and reduced motion](animation.md).

Put radios from one choice set under one dedicated semantic parent, usually an `NX_ROLE_GROUP` node. When a later sibling is selected in the same frame, the control clears the earlier sibling's checked semantic state and visual mark. Native accessibility action dispatch, text alignment helpers and richer control styling remain pending.

## Value controls

`nx_slider` maps a captured pointer position across its horizontal bounds to a finite `[minimum, maximum]` range. `nx_drag_value` changes the value by captured horizontal movement times `units_per_pixel`, including movement while the pointer is outside the bounds. Both clamp and snap to a positive `step`. When focused, Left/Down and Right/Up move by one step, Page Down/Up by ten steps, and Home/End select the endpoints. Key repeat events apply another step. The application owns the `double` value; the call updates it only after drawing and semantic registration succeed.

`nx_value_control_desc.control` supplies the stable ID, accessible name, bounds, disabled state and optional visible text layout. Both calls register a slider semantic node with increment, decrement and set-value capabilities. Its copied numeric value string reflects the updated model in the same frame. The current drag-value visualization is a marker on a track; applications can provide a text layout for a visible numeric label. Vertical sliders and native accessibility action dispatch remain pending.

`nx_numeric_parse` validates an ASCII decimal against finite bounds without depending on the process locale. `nx_numeric_input_apply_event` filters text events to digits, sign, decimal point and exponent characters, while reusing `nx_text_buffer` for selection, deletion and undo. Incomplete or out-of-range drafts remain editable; Enter commits only a valid draft to the caller-owned number. The application can call this helper for a custom focused editor.

`nx_numeric_field` owns a draft buffer and committed number. Create it with an initial value and optional undo budget, then register `nx_numeric_field_widget` each frame with a stable ID, bounds, font collection, integer pixels per em, glyph cache budget and validation range. The widget routes focused key/text events, moves the caret on pointer press, draws the current text, selection and caret inside its clip, and records the draft as its semantic value. It scrolls horizontally to keep the focused caret visible. Invalid drafts set `NX_SEM_INVALID` and use the erFor border. `nx_numeric_field_set_value` atomically replaces draft and committed value for programmatic updates and clears undo history. Query the committed value and borrowed draft with `nx_numeric_field_value` and `nx_numeric_field_text`.

`nx_text_field` provides general UTF-8 editing with the same focus, selection and painting path. Create it with initial text and an optional undo budget, then register `nx_text_field_widget` each frame. Set `multiline` in `nx_text_field_desc` to wrap inside the supplied bounds, insert a line break on Enter, and move the caret between visual lines with Up/Down; Shift extends the selection. The single-line field scrolls horizontally and the multiline field scrolls vertically to keep the focused caret visible. A single-line field reports Enter through `out_submitted` for that frame. It rejects an existing draft containing a line break; use `nx_text_field_set_text` to replace the draft and clear its undo history. The optional validation callback receives the current borrowed draft before and after focused edits. Its return value controls `out_valid`, `NX_SEM_INVALID` and the erFor border in the same frame. The callback should be free of side effects because painting can be retried. Query the borrowed draft and selection with `nx_text_field_text` and `nx_text_field_selection`.

Supply `nx_text_field_desc.clipboard` to enable Ctrl+C, Ctrl+X and Ctrl+V. Its read/write callbacks use the same UTF-8 length and buffer contract as `nx_window_clipboard_get_text` and `nx_window_clipboard_set_text`; `nx_text_clipboard_for_window` fills the callbacks for an existing native window. A missing or temporarily unavailable clipboard leaves the draft unchanged. Single-line paste turns CR/LF line breaks into spaces; multiline paste preserves line breaks. Cut deletes the selection only after a successful copy.

Create a password entry with `nx_text_field_create_password`, then set `nx_text_field_desc.password` for every widget call. A mismatch between constructor and descriptor, or a password field combined with `multiline`, returns `NX_ERROR_ARGUMENT`. The field paints one `*` per extended grapheme cluster, translates caret and pointer positions back to source UTF-8 byte boundaries, marks the semantic node `NX_SEM_PROTECTED`, and leaves its semantic value empty. Ctrl+C and Ctrl+X do nothing; Ctrl+V remains available. Its buffer has no undo history and overwrites NexaUI-owned plaintext buffers before freeing them after edits, replacement or destruction. Paste scratch storage is also overwritten before release. The application still receives real text through `nx_text_field_text` and its optional validation callback. Caller-owned text, OS input queues, native IME presentation, paging and process dumps are outside this wiping contract; native accessibility bridge handling remains open.

Both fields own copied glyph masks in the frame and can be retried after a painting failure without applying the same events twice. Edits already processed remain in the field after such a failure. Scroll offsets keep the caret visible but do not yet respond to wheel or touch gestures. The general text field passes its drawn caret to native IME placement when `ime_window` is supplied; Windows positions native candidates, while X11 updates the preedit spot when its input method supports it. At frame end, an ordinary focused field selects Windows or X11 in-field preedit or activates Wayland text-input-v3/v1, and releases that mode when focus leaves or the field is omitted. Wayland password fields request sensitive content handling, send no password surrounding text, draw masked preedit, and accept committed IME text; Windows and X11 password fields retain their basic/native input path. Keep the borrowed window alive until the context has ended its last frame or has been destroyed. Preedit from Windows, X11 callback-style XIM, and Wayland v3/v1 is inserted and underlined visually without editing the committed draft. macOS preedit presentation and native accessibility action dispatch remain pending. Clipboard shortcuts currently belong to the general text field; the numeric field does not handle them. The fields use the final frame focus state for event routing; per-event focus changes within a single queued frame are not distinguished yet.

With Wayland text-input-v3, a focused ordinary text field also publishes up to 4000 UTF-8 bytes around the cursor and complete selection. It checks the editor ID and a revision of the draft and selection before applying a compositor deletion or committed text. Deletion counts use UTF-8 bytes outside the selection; malformed or stale requests leave the draft unchanged. If the selection alone exceeds the protocol limit, the field advertises empty context while retaining its editor identity. Password fields never publish their draft.

## Containers and tabs

`nx_panel` and `nx_group` register painted semantic containers. Pass an arranged rectangle and stable ID in `nx_container_desc`, then register child widgets with that ID as their semantic parent. An optional title layout is drawn at `label_origin`; the application owns the layout and font bytes through the call. The standalone layout tree still determines geometry, so container calls do not measure or arrange children.

`nx_collapsible_section` registers a group and a separate focusable header button. Its container ID is the parent for content widgets, and `header_id` must be a different stable ID. The caller owns `expanded` and registers content children only when the returned value is nonzero. Pointer clicks and Enter/Space toggle the value; the group and header expose `NX_SEM_EXPANDED`, and the header advertises the next expand/collapse action. A disabled header does not toggle. If painting fails, the call removes both semantic nodes and the hit region and leaves `expanded` unchanged, so it can be retried in the same frame.

`nx_tab` registers one focusable tab and writes its ID to the caller-owned `selected_id` on activation. Register sibling tabs under the same parent, then register one `nx_tab_panel` for the selected page and add its children. A later sibling selected in the same frame clears the earlier tab's selected semantic state and visual fill. Tab traversal and Enter/Space work through the existing focus system; arrow-key navigation within a tab strip remains pending. Container painting and tab selection roll back on drawing erFors.

`nx_interaction_state` also reports left-button capture transitions, the last captured pointer position and movement accumulated during the frame. A release outside the region ends capture and still reports the final movement. Disabled regions suppress those fields.

## Tables

`nx_table_headers` registers a table semantic node and its column headers. Give the table, each header and each optional resize handle a stable, distinct ID. Set each column's current width and finite positive minimum and maximum; the function writes new widths into the caller-owned column array after successful drawing. A resize handle uses `resize_id`, or zero for a fixed-width column. Dragging the handle changes the width by the captured horizontal movement; Left and Right change a focused handle by ten logical pixels. Widths are clamped to their bounds. The table rectangle is the semantic extent and the header band is clipped to its top `header_height` pixels.

A sortable header toggles the caller-owned `nx_table_sort` between ascending and descending on pointer click or Enter/Space activation. Selecting a different column starts ascending. The selected header exposes `NX_SEM_SELECTED` and an `ascending` or `descending` semantic value. The application supplies its own row comparison and calls `nx_table_sort_indices` to obtain a stable index order; equal keys retain source order in both directions. The comparator receives original row indices and should have no side effects. The result buffer is unchanged if allocation or argument validation fails.

Register only visible `nx_table_row` and `nx_table_cell` nodes below the table, using their row and cell IDs as stable application keys. The row's parent is the table ID and the cell's parent is the row ID. Use `nx_virtual_list_range` from the scroll area contract to limit the number of registered rows. Row and cell calls paint their arranged rectangles and optional text layouts; they do not sort or virtualize the application data. If header painting fails, the header call removes its commands, regions and semantic nodes and leaves sort and widths unchanged, so the same frame can retry.

## Trees and tree tables

`nx_tree_flatten` takes application-owned nodes in preorder. Each node points to an active ancestor by source index, or uses `SIZE_MAX` for a root. It returns indices of nodes visible under their expanded ancestors. Call with a null output buffer to query the count, then supply enough space for the visible indices. Invalid ancestry, insufficient capacity and allocation failure leave the index buffer unchanged. A caller can use the visible count with `nx_virtual_list` and register only the range returned by `nx_virtual_list_range`.

`nx_tree` registers a painted `NX_ROLE_TREE` container. `nx_tree_item` registers a focusable `NX_ROLE_TREE_ITEM` and, for a branch, a separate focusable expander button. The item rectangle selects the caller-owned stable ID; its expander rectangle toggles the caller-owned expanded flag. Enter/Space activate either focused region, and Left/Right collapse or expand a focused branch. The item and expander report expanded state, while the selected item reports selected state. A later item selected in the same frame clears the previous item's selection state and fill. The application registers descendants only when their ancestors are expanded. Item label layouts and indentation are positioned by the application.

For a tree table, register `nx_table_headers`, then visible `nx_table_row` and `nx_table_cell` nodes. Place `nx_tree_item` inside the first cell and register additional cells under the same row. This yields a table → row → cell → tree item semantic path while retaining sort, width and tree expansion models in application data. Tree item painting and state updates can be retried after failure in the same frame.

## Popups, modals and tooltips

Register an overlay after background widgets so its backdrop and panel are visually on top. `nx_popup_begin` and `nx_modal_begin` accept an `nx_overlay_desc` with distinct panel and backdrop IDs, a named panel rectangle, and optional outside-click or Escape dismissal. Register interactive children with the panel ID as parent, then call `nx_overlay_end`. The returned `out_dismissed` tells the application to omit the overlay in its next frame. Modal panels dim the full window with the theme shadow color; popups use the same input scope without dimming. Both expose a named popup or dialog semantic role and trap keyboard focus among their children. Closing restores the previous focus when its region still exists. Call `nx_overlay_close` for a programmatic close, especially between frames, so the next pointer event reaches the background immediately.

An overlay must begin at the top level, outside a clip or scroll area, and only one may be built per frame. Failure while registering or painting removes the overlay's new commands, semantic node and hit regions, allowing a retry in the same frame. `nx_tooltip` paints a named, noninteractive semantic tooltip; the application chooses when to show it and positions it with its normal layout data. The headless tests cover keyboard cycling, focus restoration, outside-click and Escape dismissal, programmatic closure, rendering and allocation-failure retry. Native screenreader action dispatch and platform-specific overlay windows remain pending.

## Menus and bars

`nx_menu_bar`, `nx_menu`, `nx_toolbar` and `nx_status_bar` register painted semantic containers with the corresponding roles. Put `nx_menu_item` children under a menu bar or menu. A menu bar item can open a popup through `nx_popup_begin`; register a menu inside that popup and its items below the menu ID. Toolbar controls can use existing buttons under the toolbar ID, and status content can use labels under the status ID. The application arranges all rectangles and decides which popup is visible.

## Command palette and searchable select

`nx_command_palette` and `nx_searchable_select` share a search popup. The application creates a single-line `nx_text_field`, stores its borrowed pointer in `nx_search_state.query`, and supplies a `nx_search_popup_desc` with a named popup, child search field, result list bounds, row height and stable option IDs. Call the widget while the popup is visible. A searchable select can use a separate button as its collapsed trigger; the application owns that trigger and its open state. Both widgets return `out_dismissed` for Escape, outside click or selection, and `out_activated_id` for Enter or a result click. The searchable select also commits `state.selected_id`; a command palette leaves it unchanged so the application can dispatch the returned command ID.

The query field keeps keyboard focus while typing. Up/Down move the highlighted enabled result, wrapping at the ends and skipping disabled options. Enter activates the highlight. Tab reaches result rows, and pointer clicks activate them. The result list scrolls by wheel and follows keyboard navigation. Rows and the empty state have accessible names and semantic roles; the selected item is exposed for searchable select. Names are shaped and painted automatically with the query field's font collection, or the caller can provide pre-shaped row and empty-state layouts. A failed composite registration rolls back its frame nodes and commands, and may be retried in the same frame without applying the same text event twice.

`nx_search_filter` supplies the same stable filter independently of the popup. It performs locale-independent ASCII case folding and an exact UTF-8 byte match for non-ASCII text. Search results preserve option order. A small output buffer remains untouched and reports the required match count. Full Unicode case folding, ranking, asynchronous providers and virtualized result creation are later work.

The color picker and preset selector are documented with the [theme controls](themes.md#color-and-theme-controls).

Menu bar items navigate among enabled siblings with Left/Right; menu items use Up/Down. Home and End move to the first or last enabled sibling, and Enter/Space activate the focused item. Tab follows the general focus order and remains inside an active popup. An ordinary item reports `nx_interaction_state.clicked`. A checkable item takes a caller-owned boolean and toggles it after successful painting, exposing `NX_SEM_CHECKED` in the same frame. Disabled items are skipped during arrow navigation. The menu test covers hierarchy, navigation, focus return, rendering and allocation-failure retry. Accelerator dispatch, submenu hover behavior and native menu bridges remain pending.
