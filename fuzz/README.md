# Fuzz targets and seed corpora

Configure with Clang and `-DNEXAUI_BUILD_FUZZERS=ON`, then build the five
`nexaui_*_fuzz` targets. The SFNT corpus starts from a deterministic 512-byte
font generated by `make_sfnt_seed.c` and `tests/fixture_font.h`. GSUB and GPOS
seeds come from `make_gsub_seed.py` and `make_gpos_seed.py`. Run
`python3 fuzz/make_text_seeds.py` to regenerate the text corpus. The text
target exercises UTF-8 validation, grapheme and word boundaries, line breaks,
selection, navigation, edits and undo/redo. Invalid UTF-8 is also fed to the
validator.

The GPOS corpus also includes seven `NXP2` seeds generated from the public-API
mark tests: after building tests, run `nexaui_gpos_mark_tests --write-seeds
fuzz/corpus/gpos` (use the executable's build directory). The target accepts
legacy raw GPOS or a 16-byte `NXP2` header containing big-endian GPOS/GDEF/GSUB
lengths followed by those three tables. It runs fixed base/mark, ligature and
nested-ligature sequences plus a mutated sequence through GSUB, metrics, GPOS
and attachment resolution. The campaign runner uses `-max_len=2048` for GPOS
so the combined seeds fit. This exercises the implemented subset; it is not
complex-script conformance or a real-font corpus.
Run `python3 fuzz/make_layout_seeds.py` after generating the text corpus to
create focused wrapping, hard-break, paragraph-separator, bidi, combining-mark and whitespace
cases. The layout target uses a borrowed synthetic font face and checks lines,
glyphs, carets, hit testing, selection geometry and copied text under three
direction/width combinations.

Regenerate the SFNT file with:

```sh
cc -std=c17 -Iinclude fuzz/make_sfnt_seed.c -o /tmp/nexaui-make-sfnt-seed
/tmp/nexaui-make-sfnt-seed > fuzz/corpus/sfnt/fixture.sfnt
```

Run each target against a copy of its seed directory so libFuzzer can add
coverage discoveries without changing the source corpus. For example:

```sh
cmake -S . -B build-fuzz -G Ninja -DCMAKE_C_COMPILER=clang \
  -DNEXAUI_BUILD_FUZZERS=ON -DNEXAUI_BUILD_TESTS=OFF \
  -DNEXAUI_BUILD_EXAMPLES=OFF
cmake --build build-fuzz --target nexaui_sfnt_fuzz nexaui_gsub_fuzz \
  nexaui_gpos_fuzz nexaui_text_fuzz nexaui_layout_fuzz
mkdir -p /tmp/nexaui-fuzz-corpus
cp -R fuzz/corpus/sfnt fuzz/corpus/gsub fuzz/corpus/gpos fuzz/corpus/text \
  fuzz/corpus/layout \
  /tmp/nexaui-fuzz-corpus/
ASAN_OPTIONS=detect_leaks=0 UBSAN_OPTIONS=halt_on_error=1 \
  build-fuzz/nexaui_text_fuzz \
  /tmp/nexaui-fuzz-corpus/text -seed=1800 -runs=10000 -max_len=512
ASAN_OPTIONS=detect_leaks=0 UBSAN_OPTIONS=halt_on_error=1 \
  build-fuzz/nexaui_layout_fuzz /tmp/nexaui-fuzz-corpus/layout \
  -seed=1800 -runs=10000 -max_len=256
python3 tools/report_script_coverage.py
```

The Alpine 3.24 libFuzzer runtime used for the recorded campaign reports a
small allocation in its own `FuzzerDriver` at process exit. The command above
disables LeakSanitizer for that environment; AddressSanitizer and
UndefinedBehaviorSanitizer remain active. This is not a leak audit of the
NexaUI targets. The dated campaign and limits are in
`docs/quality/text-fuzz-report.md`.

`tools/run_fuzz_campaign.py --build-dir build-fuzz --output-dir out/fuzz-run-1`
automates all five bounded runs against fresh copies and writes logs, crash
artifacts, hashes and exit codes. It refuses an existing output directory or
one inside the source corpus. Optional CI jobs and the supported-toolchain
report are documented in `docs/quality/sanitizers.md`.
